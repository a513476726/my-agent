# Spec Delta

## Purpose

提供可被标准聊天客户端直接接入的对话能力，并把工具调用结果与会话引用持久化，使回答可回溯、可审计。

## ADDED Requirements

### Requirement: OpenAI 兼容接口

系统 SHALL 提供 `GET /v1/models` 与 `POST /v1/chat/completions`，并 MUST 支持流式（SSE）响应。

#### Scenario: 流式返回
- **WHEN** 客户端以流式模式发起对话请求
- **THEN** 系统分块返回增量内容，并在结束时给出终止标识

#### Scenario: 模型列表
- **WHEN** 客户端请求模型列表
- **THEN** 系统返回当前可用模型标识

### Requirement: 工具编排

智能体 SHALL 能在单轮对话中编排多个工具，包括知识检索、文件读取与 Git 查询。所有工具调用 MUST 限定在会话绑定的项目范围内。

#### Scenario: 组合使用知识与代码
- **WHEN** 用户询问某需求在代码中的实现
- **THEN** 智能体先检索知识库确定需求口径，再读取对应仓库文件给出实现位置

#### Scenario: 工具调用越界被拒绝
- **WHEN** 工具请求的路径不属于绑定项目
- **THEN** 该次工具调用失败，并向模型返回失败原因

### Requirement: 会话持久化

每一轮对话 MUST 落库，包含角色、内容、工具调用摘要与引用；会话 MUST 归属到一个项目。

#### Scenario: 查询历史会话
- **WHEN** 用户打开某项目的历史会话
- **THEN** 系统返回按时间排序的消息及每条的引用信息

### Requirement: 引用可追溯

基于知识库的回答 MUST 附带可定位引用；引用信息 SHALL 包含文档标识与章节路径。

#### Scenario: 回答带引用
- **WHEN** 回答引用了知识库内容
- **THEN** 响应中每条引用可定位到对应文档与章节

### Requirement: 缺上下文时拒绝

未绑定项目的请求 MUST 被拒绝执行工具，系统 SHALL 提示用户先选择项目。

#### Scenario: 无项目绑定的对话
- **WHEN** 请求未携带项目标识
- **THEN** 系统仅返回提示，不执行任何工具调用

### Requirement: 失败可见

工具调用失败时，系统 MUST 在响应中体现失败原因，不得静默吞掉或伪造成功结果。

#### Scenario: 工具超时
- **WHEN** 某次工具调用超时
- **THEN** 响应中包含该工具失败的说明，后续推理基于该事实继续
