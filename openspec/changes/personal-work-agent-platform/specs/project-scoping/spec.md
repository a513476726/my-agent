# Spec Delta

## Purpose

让多个被分析的代码项目在同一平台内并行运行而互不串味。通过与每次对话和任务绑定的显式项目上下文，约束检索范围与代码访问边界。

## ADDED Requirements

### Requirement: 项目登记与启用

系统 SHALL 允许登记被分析的代码项目，包含名称、路径、版本控制类型与启用状态。项目路径 MUST 唯一，重复登记 SHALL 被拒绝。

#### Scenario: 登记新项目
- **WHEN** 管理员提交名称、路径与版本控制类型
- **THEN** 系统创建项目记录并返回项目标识

#### Scenario: 重复路径被拒绝
- **WHEN** 管理员提交的路径与已有项目相同
- **THEN** 系统拒绝创建并返回明确的冲突错误

#### Scenario: 停用项目
- **WHEN** 管理员将项目置为停用
- **THEN** 该项目不再参与定时任务，历史数据仍可查询

### Requirement: 显式项目上下文

每次对话与会话内工具调用 MUST 绑定一个 `project_id`。缺少项目上下文时，系统 SHALL 拒绝执行工具并提示用户选择项目，不得自行猜测。

#### Scenario: 无上下文时拒绝
- **WHEN** 请求未携带 `project_id`
- **THEN** 系统不执行任何工具调用，并返回「请先选择项目」的提示

#### Scenario: 绑定后限定范围
- **WHEN** 对话绑定了项目 A
- **THEN** 该会话内的检索与代码访问仅限项目 A

### Requirement: 跨项目检索隔离

知识检索 SHALL 只返回绑定项目命名空间内的结果。不属于任何项目的通用规范 MUST 存放在独立的共享命名空间，且仅在被显式请求时可访问。

#### Scenario: 检索不跨项目
- **WHEN** 在项目 A 的会话中检索某关键词
- **THEN** 结果集合中不出现项目 B 的文档

#### Scenario: 访问共享规范
- **WHEN** 检索显式指向共享命名空间
- **THEN** 系统返回通用规范文档，且不混入业务项目内容

### Requirement: 代码访问范围限制

文件读取与 Git 查询 MUST 限定在项目登记路径内。访问登记路径之外的资源 SHALL 失败并记录审计日志。

#### Scenario: 越界读取被拒绝
- **WHEN** 工具尝试读取项目路径之外的绝对路径
- **THEN** 请求失败，且不返回文件内容

#### Scenario: 对只读挂载写入被拒绝
- **WHEN** 工具尝试在被分析仓库内创建或修改文件
- **THEN** 操作失败，仓库内容保持不变
