# Spec Delta

## Purpose

按日、周、季度自动产出代码变更总结，并把报告正文与条目持久化到数据库，使历史产出可检索、可追溯、可复用。

## ADDED Requirements

### Requirement: 定时与手动触发

系统 SHALL 按配置的 cron 表达式触发报告任务，并 MUST 支持管理员手动触发同一任务。

#### Scenario: 定时触发
- **WHEN** 到达配置的执行时间且任务处于启用状态
- **THEN** 系统为每个启用项目创建一次运行记录并开始执行

#### Scenario: 手动触发
- **WHEN** 管理员手动触发某任务
- **THEN** 系统按与定时触发相同的流程执行，并在运行记录中标注来源为手动

### Requirement: 运行幂等

同一任务、同一项目、同一周期 MUST 只产生一份报告。已存在成功运行的周期，重复触发 SHALL 被跳过并返回已有结果引用。

#### Scenario: 同日重复触发
- **WHEN** 同一项目在当天已成功生成日报后再次触发
- **THEN** 系统跳过执行，不产生第二份报告

#### Scenario: 失败后重试
- **WHEN** 上一次运行失败后再次触发
- **THEN** 系统允许重新执行并更新该次运行的状态

### Requirement: 故障隔离

单个项目的执行失败 MUST 只影响该项目自身的运行记录，不得阻断其他项目的执行。

#### Scenario: 单仓库损坏
- **WHEN** 某项目路径不存在或 Git 命令失败
- **THEN** 仅该项目的运行记录标记为失败并附错误信息，其他项目正常完成

### Requirement: 报告入库

报告正文与报告条目 MUST 存储于数据库，本地文件 SHALL 仅作为可选导出，不得作为事实来源。

#### Scenario: 查询报告
- **WHEN** 用户在管理后台打开某份报告
- **THEN** 系统从数据库读取正文与条目并展示

#### Scenario: 导出报告
- **WHEN** 用户选择导出
- **THEN** 系统生成文件，且数据库中的报告不受影响

### Requirement: 条目可追溯

每条报告条目 MUST 关联所属项目与来源提交范围（起止提交标识），使结论可回溯到具体变更。

#### Scenario: 回溯条目来源
- **WHEN** 用户查看某条报告条目
- **THEN** 系统展示该条目对应的项目与提交范围

### Requirement: 多项目并行

系统 SHALL 支持多个项目的报告任务并行执行，且并发执行不得导致报告内容互相串入。

#### Scenario: 并行执行
- **WHEN** 多个项目同时触发日报任务
- **THEN** 每份报告只包含自身项目的内容
